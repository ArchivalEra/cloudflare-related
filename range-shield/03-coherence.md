# 03-coherence — 一致性规则（RS4 #24）

> 目标：击穿与脏读用同一套机制解决。只认 version，不认时间。

## 1. version 翻转

* 写入 / 上游 revalidation 报新 etag → `version` 翻转（新值必须不可预测回绕，推荐内容 hash 或单调代号）。
* 翻转瞬间：旧 version 全分片**逻辑失效**（查询侧直接视为缺失），物理删除懒做（后台扫 + TTL 兜底）。
  不做“逐分片失效通知”——分片数上万时通知即风暴本身。
* 无 version 的存储（如裸 mtime+size 合成）：标险接入，翻转检测有窗口期，脏读自负（00 已警告）。

## 2. single-flight 是唯一的冷路径

* 任何缺失分片只经过 flight 回填；不存在“旁路回源”（debug 通道除外，生产编译关闭）。
* 回填原子性：分片要么完整可见，要么不可见；半片永不进缓存（上游断流 → flight 失败 → 同窗同失败，不写半片）。
* 因此：**击穿不可能**（flight 合并），**脏读不可能**（旧版不可见 + 半片不写）——同一机制的两个推论，无需两套代码。

## 3. 重验 outcomes

| 上游重验结果 | 在途分片 | 已缓存分片 |
|---|---|---|
| 304（未改） | 正常结算回填（version 不变） | 续命（刷新 TTL/新鲜度） |
| 新 etag | 按新 version 结算；在途旧窗丢弃结果不回填（01 规则） | 旧版逻辑失效（本节 §1） |
| 错误（5xx/超时） | 同窗同失败；stale 策略另行定（默认不 serve-stale，有明确需求才开，RFC 5861 门槛） | 保持旧版可见（错误不驱逐，见 pingora-cache 篇 stale 默认关） |
